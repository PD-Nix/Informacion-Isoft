Modelo de dominio


Modelo visual que identifica los objetos del problema y sus relaciones de manera abstracta (el concepto del problema) 

Para crear un modelo de dominio:
Paso 1: Identificar los posibles objetos del problema.

Se puede usar un *análisis gramatical* en el cual se toma la descripción del problema -negocio-
tomando  los sustantivos como *posibles objetos del sistema* y los verbos como acciones y relaciones de los mismos.

Paso 2:  Extraer de los  *posibles objetos del sistema* los que verdaderamente son parte del modelo de dominio (parte del problema, no de la solución) 

Para esto se hace el siguiente análisis para cada uno de los objetos que se identifico en el paso 1: 
¿Si se retira este objeto del contexto del problema este seguiría siendo completo? Es decir, que objetos no son relevantes o indispensable en la definición del problema, si son indispensable se quedan, si no se van.

Paso 3: Se representan los objetos gráficamente.

Se empieza armar el grafico del modelo de dominio, representando a los objetos ya definidos mediante las clases conceptuales de UML. 

Paso 4: Establecer las relaciones entre los objetos. 

Este establecimiento debe poseer un verbo, una multiplicidad y un orden que sea coherente con el modelo de negocio 

----
Nota:  El modelo de dominio es una diagrama de objetos, no de clases.
